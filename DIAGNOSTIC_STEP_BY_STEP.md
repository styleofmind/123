# Пошаговый план диагностики и подготовки двух ПК

## Цель

Сначала полностью обследовать оба компьютера, не устанавливая тяжёлые AI-компоненты вслепую. После получения отчётов определить:

- какое железо есть на каждом ПК;
- какой GPU и сколько видеопамяти;
- сколько ядер/потоков CPU;
- сколько RAM;
- сколько свободного места;
- какие версии Windows и Python;
- есть ли NVIDIA CUDA / драйверы;
- какие AI-инструменты уже установлены;
- какая скорость CPU на простом локальном тесте;
- какие сетевые возможности доступны;
- что разумно запускать на каждом ПК.

Основной принцип:

**PC1 (Windows 11, 16 GB, более мощный) → тяжёлые задачи.**  
**PC2 (Windows 7, 8 GB, без постоянного интернета) → лёгкие задачи.**

Но окончательное распределение задач делаем только после диагностики.

# ШАГ 4. Ничего тяжёлого пока не устанавливать

До анализа отчётов **не устанавливать**:

- CUDA;
- PyTorch с CUDA;
- TensorFlow;
- большие модели;
- Ollama;
- ComfyUI;
- Stable Diffusion;
- YOLO;
- OCR-модели;
- большие Python-пакеты.

Сначала определяем оборудование и совместимость.

Это позволит не занять диск ненужными компонентами и не поставить неправильную сборку CUDA/PyTorch.

# ШАГ 5. Определить архитектуру AI-задач

После диагностики разобьём будущую систему на отдельные задачи.

## Фото автомобилей

Планируем обработку:

1. обнаружение автомобиля;
2. определение типа автомобиля;
3. определение спецтранспорта;
4. определение марки/модели, если качество изображения позволяет;
5. поиск номерного знака;
6. OCR номера;
7. оценка высоты:
   - до 2 м;
   - до 2,6 м;
   - выше 2,6 м;
8. если выше 2,6 м — попытка определить количество осей;
9. сохранение результата в структурированный JSON/CSV;
10. сохранение исходного изображения и, при необходимости, изображения с разметкой.

Категории спецтранспорта:

- скорая помощь;
- полиция;
- пожарная/аварийная служба;
- другой спецтранспорт;
- неизвестно.

# ШАГ 6. Видео

Если появятся видео, не обязательно анализировать каждый кадр.

Первый вариант:

- извлечь примерно 60 кадров из видео;
- удалить почти одинаковые кадры;
- оставить информативные;
- выполнить детекцию;
- выбрать кадры с лучшим номерным знаком;
- отдельно обработать лучшие кадры OCR.

После теста можно подобрать оптимальное количество кадров.

---

# ШАГ 7. Проверить скорость

После определения железа сделаем небольшой benchmark.

Проверим:

- CPU inference;
- GPU inference, если GPU подходит;
- OCR;
- детекцию автомобилей;
- обработку одного фото;
- обработку серии фотографий.

Цель — получить реальные значения на конкретных ПК, а не ориентироваться на теоретические цифры.

# ШАГ 11. Проверить PC2

PC2 работает с:

- Windows 7;
- Python 3.8;
- 8 GB RAM;
- без постоянного интернета.

Поэтому сначала определяем, какие лёгкие задачи он реально сможет выполнять.

Возможные роли:

- подготовка изображений;
- извлечение кадров;
- простая фильтрация;
- конвертация;
- предварительная обработка;
- лёгкий OCR;
- запуск небольших CPU-моделей;
- передача результатов по локальной сети.

Тяжёлые модели на PC2 устанавливать только после проверки железа.

---

# ШАГ 12. Интернет для PC2

Если понадобится доступ PC2 в интернет через PC1 без прав администратора, основной вариант — **Python HTTP/HTTPS proxy**.

Важно:

- это не полноценный Windows NAT;
- приложения должны поддерживать proxy;
- системную маршрутизацию Windows без администратора гарантировать нельзя.

Сначала проверяем, действительно ли это необходимо.

---

# ШАГ 13. Локальная сеть

Если PC1 и PC2 находятся в одной LAN:

`PC2 → LAN → PC1 → Internet`

Можно организовать отдельный пользовательский proxy-сервис на PC1.

Например:

`PC1:8080`

PC2 указывает proxy:

`http://IP_PC1:8080`

После этого проверяем:

1. доступность PC1 с PC2;
2. открытие TCP-порта;
3. HTTP;
4. HTTPS;
5. DNS;
6. работу конкретных программ.

---

# ШАГ 14. Удалённый доступ

Если потребуется управление ПК через Desktop Commander или аналогичный инструмент:

1. сначала проверяем сеть;
2. затем проверяем исходящие соединения;
3. затем устанавливаем необходимый компонент;
4. проверяем запуск без администратора, если это возможно;
5. только после этого строим автоматизацию.

Не следует сразу менять системные настройки Windows или firewall.

Для каждого этапа считаем отдельно:

- detection accuracy;
- classification accuracy;
- OCR accuracy;
- номер найден / не найден;
- номер читается полностью / частично / не читается;

- правильность определения спецтранспорта;

Это позволит понять, где действительно требуется дообучение.

# ШАГ 18. Дообучение

Не начинаем обучение собственной модели сразу.

Сначала:

1. готовая модель;
2. тест;
3. сбор ошибок;
4. разметка ошибок;
5. небольшой собственный dataset;
6. повторный тест;
7. только потом fine-tuning.

Если готовая модель решает задачу достаточно хорошо, обучение собственной модели может оказаться ненужным.

---

# ШАГ 19. Параллельная обработка

После benchmark проверим:

- один процесс;

Не предполагаем заранее, что два AI-процесса быстрее одного.

При 16 GB RAM два процесса могут начать конкурировать за:

- RAM;
- VRAM;
- CPU;
- диск.

Выбираем количество worker'ов по реальному benchmark.

# Важные ограничения

## Не требуются права администратора

Диагностический скрипт рассчитан на обычного пользователя.

Некоторые отдельные сведения Windows могут быть недоступны обычному пользователю — это нормально.

## Интернет

Диагностика может показать ошибки HTTPS на старой Windows 7 из-за TLS/сертификатов. Это не обязательно означает отсутствие сетевого соединения.

## WMIC

На новых версиях Windows `wmic` может отсутствовать. Скрипт использует PowerShell fallback там, где это предусмотрено.

## Безопасность

Не отправлять в отчёт:

- пароли;
- API keys;
- cookies;
- токены;
- приватные ключи.

Если такие значения случайно появятся в выводе сторонней программы, перед передачей отчёта их можно удалить.
